Privacy policy

What the Gmail alert connection uses.

This policy covers the Gmail email-alert integration in the owner's personal ryGRO Monitor application and this informational website. It describes the implemented local alert worker and Google authorization helper. Other sensor, camera or equipment integrations have separate data flows and are not covered by this Gmail integration policy.

Google access

The application requests only https://www.googleapis.com/auth/gmail.send. This lets it send email from the Google account authorized by the owner. The application does not request or use permission to read existing emails, list messages, access contacts or delete mail. The owner selects the intended Google account during authorization; the application does not request a profile or account-identity scope.

Information processed

  • Authorization information: the OAuth client identifier and client credential, the send-only permission, a refresh token and temporary access tokens.
  • Mail configuration: the approved email address and alert timing preferences. The application currently restricts outgoing mail to its single approved recipient.
  • Alert content: descriptions of sensor availability, equipment availability, recovery events, and relevant temperature, humidity, estimated VPD or target-limit values. A test email contains a connection-test message.
  • Delivery records: incident details, queued notifications, internal message identifiers, attempt counts, timestamps and limited delivery/error status.

The email worker does not include camera photographs, camera video, an inbox export, a full sensor-history export or equipment passwords in alert messages.

How information is used and shared

Local monitor readings are evaluated on the owner's PC to decide whether an alert is due. OAuth credentials are used to obtain permission to send. The application transmits authorization requests to Google and the resulting alert message to the Gmail API over HTTPS. Google processes the message for delivery to the approved recipient. Delivered and sent messages are then stored according to the Google account's settings and Google's policies.

The alert integration does not sell this information, use it for advertising, send it to an analytics service, or use it to train AI models. Its Google API data use is limited to providing the email-alert functionality described here, consistent with the Google API Services User Data Policy, including its Limited Use requirements.

Local storage and protection

The refresh credential and associated OAuth configuration are stored in a local file encrypted with Windows Data Protection API (DPAPI) for the Windows user running the application. Access tokens are used in memory and are not deliberately persisted by this integration. Error messages are reduced to defined status codes rather than exposing provider responses or credentials.

Alert settings, incident details and delivery records are stored locally in ordinary JSON files; they are not encrypted by the email worker. Windows access controls and the owner's PC security therefore also matter. Encryption does not protect against every threat, including malicious software running with the owner's account access.

Retention and removal

The integration has no fixed time-based deletion schedule for its stored authorization or delivery ledger. It removes queue items after successful delivery and clears resolved incidents after a recovery notification is sent; some delivery metadata remains. Locally stored files may also exist in owner-managed backups.

Turning off alerts stops automatic alert delivery; it does not revoke Google access or delete local records. The owner can revoke this application's access through the Google Account connections page. Local credentials and alert records can be removed separately through maintenance of the installation and any backups. Previously delivered email must be deleted separately in Gmail. This application does not have permission to delete it.

This informational website

These public information pages are intended for GitHub Pages hosting. GitHub may process routine request metadata to deliver and protect the website under its General Privacy Statement. We have not added analytics scripts or cookies to these pages.

The website has no monitor login, live sensor readings, camera feed or Google authorization credentials. It does not connect visitors to the private monitor. If you contact the support email shown on the Google consent screen, your email address and message will be used to respond to your request.
